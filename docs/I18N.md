# Internationalisation

SkillProof translates two things:

1. **The interface**: every label, button and message, through `_()` and JSON catalogues.
2. **Content people write**: profiles, job ads, feedback and cover notes, translated on demand by `/api/translate`.

## How a language is chosen

1. `?lang=xx` in the URL (also saved for later visits)
2. Session
3. `lang` cookie
4. The browser's `Accept-Language`
5. English

`<html lang dir>` is set from the language, and the CSS mirrors the layout for RTL (`[dir=rtl]`; icons that point a direction use `.flip-rtl`).

## Writing translatable templates

```jinja
{{ _('Add evidence') }}
{{ _('You applied {when}. Status:', when=existing.created_at|ago) }}
{{ _(SKILL_STATUSES[skill.status]) }}            {# dictionary values are translation keys too #}
```

- Keys are the **English text itself**. Placeholders use `{name}` and are filled with keyword arguments.
- Do **not** assign to `_` in templates (`{% set _ = … %}` shadows gettext). Use `_x` instead.
- Text people write themselves goes in `<span data-tr>…</span>`, never in `_()`.
- `tools/wrap_strings.py <template>` wraps leftover plain text in `_()` automatically (it protects Jinja tags while doing so).

## Catalogues

`translations/<code>.json` is a flat map from English to the translation:
```json
{ "Add evidence": "Ongeza ushahidi", "You applied {when}. Status:": "Uliomba {when}. Hali:" }
```
`translations/<code>.machine.json` lists keys that were **machine-drafted** and still need a native speaker's review.

## CLI

```bash
python i18n.py                     # coverage per language, and strings awaiting native review
```
```bash
python i18n.py --translate sw      # draft missing strings for one language with Claude
```
```bash
python i18n.py --translate all     # every language (~150 API calls, about US$10)
```

The translator:
- collects every key from templates and Python (`extract_strings`), plus dynamic ones such as status labels, wizard steps and password rules;
- sends batches of 70 with a **glossary** from human translations so terms stay consistent;
- checks that every `{placeholder}` is kept, and skips any string where one is missing;
- saves after every batch, so re-running continues where it stopped.

## Adding a language

1. Add `"xx": ("Native name", "English name", "ltr")` to `LANGUAGES` in `i18n.py`.
2. Run `python i18n.py --translate xx`.
3. Have a native speaker review the keys listed in `translations/xx.machine.json`, then remove them from that file.

## Content translation

Pages wrap user-written text in `data-tr`. When AI is configured on the server and such text is present, a bar offers
**"Translate to <language>"**. `static/js/translate.js` sends the texts in batches of 40, swaps them in, and adds a
"Translated by AI" tooltip and a **Show original** toggle. The choice is remembered per language (`localStorage['sp-autotr']`).
The server caches every translation (`content_translations`), so a text is only translated once per language for all readers.
